# BlockLearn：实现与方案的语义对应

这是研究原型，不是已证明超过 ART/HOT 的索引，也不是已经确认新颖性的论文算法。
模型、验证器、接口适配和实验入口均位于 `src`。原来的 `trie.*`、`model.*`、`main.cpp` 是用户早期练习，保持原样，不参与新索引的构建。

## 训练是什么

区域初始目标 1024 条记录，目录目标扇出 64。对区域内排序后的第 i 个 key，监督标签是 `floor(i / block_size)`，而不是整个数据集的全局 rank。

编码从区域公共前缀后连续读取 2 / 4 / 7 字节。每字节映射为 1..256，EOS 为 0，因此空 key、内嵌 NUL 和前缀关系不混淆。编码是非递减的，截断后允许重复。浮点运算前先用整数减去段内原点，避免直接转换 63-bit 坐标丢失低位。

分段使用数据端点拟合斜率、截距，段数尝试 1 / 2 / 4 / 8（可配置上限），相同编码值不跨段。每段误差是对全部训练 key 计算的实际最大块误差。之后再次通过实际 segment 选择逻辑复核所有 key，不能用平均误差替代正确性保证。

规划尝试块大小 16 / 32 / 64，按编码字节、平均候选块数和模型内存的代价代理选出两个候选，再联合评价残差标签代价。这是**有预算的候选搜索**，不是对所有编码、分段和标签组合求全局最优。

代价代理的系数是显式启发式常量，不是实测纳秒或训练得到的硬件性能模型。真实性能仍需 benchmark 验证。

## 残差感知标签

`TagPlan` 选择最多两个字节位置，允许通过参数扩展到四个，并混合 key 长度及 EOS 信息得到 16-bit 标签。选择候选包括后缀前八字节和后续间隔位置，数量受控；不是穷举任意字符串的全部位置。

训练对每个候选配置构建 `(block, tag)` 计数，确定性抽取最多 128 个训练查询，统计其**模型候选窗口内**剩余的匹配标签数。目标还惩罚读取字节数和相对跨 64B 窗口数。实际地址对齐并不由这个估计保证。

标签不保序，也不需要保序：它只负责过滤，绝不参与目录排序或替代字符串相等验证。不能把其碰撞率当作均匀随机哈希的 `1/65536`。

基础标签数组按 64B 对齐，ID 与标签分离。32 个 16-bit 标签占 64B；但区域可能选择 16 或 64 条/块，完整查询还需要目录、记录 ID 和字符串访问，不能声称一次缓存行访问就完成查询。

四个消融版本都执行同一规划，以固定区域、编码和模型。E1 不保留基础标签，E2 换为对公共前缀后完整后缀的 FNV-1a 标签，E3/E4 使用学习得到的字节标签。这会使 E1/E2 构建也包含共同规划成本，是为了控制变量，不是它们各自独立调优后的最优版本。

## 多层目录与正确性

目录只保存子区域/子目录的最小 key 及子指针；逐层训练小模型预测子位置。模型没有通过预算时用精确有序搜索。

目录处理任意 key 的 predecessor 导航，不能仅凭“训练 key 的误差界”信任未见过的查询。每次模型预测后都检验真实 fence bracket：所属子节点必须满足 `fence[p] <= key < fence[p+1]`，首尾做边界扩展。不满足就对当前目录精确搜索。

基础区域点查不同：只要对**每个已有 key**验证其真实块在预测窗口内，并最终精确比较，就能正确回答未命中查询。若查询 key 存在，它必然在窗口内并有一致标签；因此完整检查窗口后没有相等 key，可以返回不存在。这里没有宣称模型知道任意未见 key 的精确插入 rank。

## 动态写入

E4 的新 key 先按真实范围目录路由，检查基础区和局部 delta 防重复，然后追加到该区域的增量向量。delta 按需分配，不是全局有序向量，也不要求每次维护有序性。

查询先检查所属区域 delta，再查询基础区。delta 检查独立于基础模型的公共前缀；新 key 可能在模型范围之外或缩短公共前缀。

默认 delta 达到 16 条即同步合并、排序并重新验证模型；区域超过目标大小或拟合困难时分裂。目录只更新相关路径，必要时向上分裂；记录 ID 不随全局 rank 改变。分裂/合并同步更新叶链和真实边界。

普通合并先按旧的编码长度、块大小和段数重新拟合，并逐键重新验证误差，而不是每次重跑完整参数网格。失败时才完整规划或分裂。合并优先复用旧的绝对字节位置，每八次合并或候选窗口明显扩大时检查过滤质量；候选匹配代价超过阈值才重新选择特征。碰撞增加只影响速度，不影响精确性。正常写入不是无条件 O(1)：仍有路由、重复检查、分配与摊销维护成本，合并/重训必须计时。

基础输入行在索引存活期间借用；插入行由稳定地址的 deque 持有。叶记录使用 32-bit ID，**总记录数最多 UINT32_MAX**，超过时显式报错。key 长度没有人为截断。

## 接口范围

- 所有版本支持 `bulk_load` / `find` / `scan` / `range_sum`；仅 E4 开启 `insert`。
- 重复插入不覆盖旧值，包括值为 0 和 UINT64_MAX。
- `scan` 是 unsigned-byte 有序的 `>= lower`，结果拥有字符串。
- `range_sum` 两端包含，uint64 自然溢出取模；反向区间为 0。
- `update` / `erase` 明确 unsupported，调用不修改状态。
- `scan` / `range_sum` 目前为精确功能实现，会复制/局部排序 ID；不是已经优化的扫描性能设计。
- 单线程、非持久化；尚未提供分配失败的事务式强异常保证。

## 内存与实验边界

内存统计分开给出自有结构、适配层、保留输入。基础输入的整个行向量与字符串堆容量计入 retained input，不能只报 6B/key 元数据并宣称是总内存。

当前估计不包含分配器头、deque 备用块和训练/合并临时峰值；HOT 原生统计也不含 free-list 池。报告因此不进行总内存排名，不将未知峰值填 0。

静态 E3/E4 在未发生写入前查询路径完全相同；不能把它们的噪声差异当作写优化收益。写实验用随机保留真实 key 作为插入流，不只测单调追加；插入池耗尽后实际读写数会写入报告。

## 文献与原创性

- RSS: https://arxiv.org/abs/2111.14905 — 字符串分片、有界纠错、Hash Corrector 已有。
- PGM: https://pgm.di.unipi.it/ — 分段线性预测和误差/空间取舍已有。
- ALEX: https://arxiv.org/abs/1905.08898 — 动态结构和局部维护已有。
- LITS: https://www.shimin-chen.com/papers/LITS-pvldb24.pdf — HPT、紧凑叶节点与混合选择已有。
- LINE: https://www.shimin-chen.com/papers/LINE-pacmmod26.pdf — 分组预测、组内哈希、缓存优化和细粒度维护已有。

候选研究点是“根据预测后的残差候选集合选择验证字节，并联合优化小块定位与验证成本”。组合上述部件不自动构成创新；必须补读 LITS+/LISK 等相关工作，并通过消融证明额外收益后，才能判断可发表性。没有复制这些论文/仓库的模型实现来作为自己的算法；ART/HOT 仅作为独立基线链接。
