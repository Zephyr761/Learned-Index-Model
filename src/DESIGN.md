# BlockLearn 模型架构与实现

## 1. 总体设计

BlockLearn 是一个面向变长字符串键的内存有序索引。完整配置由多层范围目录、局部分段线性模型、紧凑候选验证数组和区域增量缓冲组成。

各部分分工如下：

- 范围目录确定查询所属的叶区域，并维护区域之间的真实键序关系。
- 叶模型预测记录所在的局部块编号，将查询范围缩小为一个连续候选窗口。
- 标签数组先筛选候选记录，再通过完整字符串比较确定是否命中。
- 增量缓冲接收新键，达到阈值后在所属区域内合并、重新拟合，必要时分裂。

```text
查询 key
   │
   ▼
根目录 ── 短编码精确范围定位（可选）/ 模型辅助定位 + fence 边界验证
   │
   ▼
中间目录（按数据规模形成多层）
   │
   ▼
叶区域
   ├── 局部 delta：标签检查 → 完整 key 验证 → 命中则返回
   │
   └── 基础区：叶模型 → 候选块窗口 → 标签筛选 → 完整 key 验证
                                   （可选：先检查预测块）
                                                          │
                                                          ▼
                                                  返回 value / 未找到

叶区域之间通过 next 指针按键序连接，供有序扫描使用。
```

模型预测和标签匹配均不直接作为查找答案。范围定位以真实边界为准，点查询以完整 key 相等为准。整个索引不使用全局 CDF，也不将预测分数映射为带冲突链表的槽位。

## 2. 数据语义与存储布局

### 2.1 键值与生命周期

接口中的一条记录为 `Row { std::string key; uint64_t value; }`。键按 unsigned-byte 字典序比较：先比较公共长度内的字节，公共部分相同则短键在前。空键、内嵌 NUL、高位字节和互为前缀的不同键均按这一规则处理。

基础数据和插入数据分开存储：

| 存储 | 类型 | 用途与所有权 |
| --- | --- | --- |
| `input_` | `const std::vector<Row>*` | 借用调用者提供的基础数据，索引存活期间必须保持存活且不可修改 |
| `inserted_` | `std::deque<Row>` | 索引拥有的新增记录，追加时已有记录的地址保持稳定 |
| `Id` | `uint32_t` | 节点中的记录引用，通过 `row(id)` 取得真实 key 和 value |

基础记录的 ID 是其输入行位置；第 j 条新增记录的 ID 是 `input_->size() + j`，其中 j 从 0 开始。局部排序、合并和分裂只调整 ID 数组，不改变记录 ID。ID 因而是稳定记录标识，不是插入后需要整体更新的全局 rank。

公共前缀和目录边界使用 `string_view` 引用真实记录中的字符串。借用输入的生命周期，以及新增记录的稳定地址，共同保证这些视图的有效性。总记录数按实现限制为至多 `UINT32_MAX`。

### 2.2 统一节点结构

目录和叶区域共用 `LearnedIndex::Node`，通过 `leaf` 标记区分用途。它们不是两个独立分配的节点类型。

| 字段 | 叶区域中的用途 | 目录中的用途 |
| --- | --- | --- |
| `ids` | 按完整 key 排序的基础记录 ID | 不使用 |
| `tags` | 启用标签且模型已认证时，与 `ids` 一一对应的 16-bit 标签 | 不使用 |
| `delta` | 尚未合并的新增记录 `{id, tag}` | 不使用 |
| `children` | 不使用 | 按键范围排列的子节点所有权指针 |
| `fences` | 不使用 | 各子节点当前最小 key 的视图 |
| `short_keys` | 空的短编码目录对象 | 可选的连续 64-bit fence 编码、公共前缀与启用标记 |
| `model` | 预测局部块编号 | 预测 fence 的局部位置 |
| `tag_plan` | 选择查询标签使用的字节位置 | 不使用 |
| `tag_kind / predicted_first / planning_cost` | 新规划器选择的标签种类、扫描顺序和上次维护的成本估计 | 不使用 |
| `merges_since_features` | 标签质量检查的维护计数 | 不使用 |
| `next` | 下一个叶区域 | 不使用 |

启用标签的基础区采用 ID / 标签分离的数组布局：只有标签匹配的候选才访问记录并比较完整 key。`tags` 的数组起始地址按 64B 对齐；`ids`、真实字符串和整个节点不由此获得同样的对齐保证。

“块”是 `ids` / `tags` 中连续位置的逻辑分组，不单独分配块对象，也不为每个块配置一个链表。

## 3. 局部分段线性模型

### 3.1 模型输入与监督目标

设一个叶区域有 n 条有序基础记录，逻辑块大小为 B。第 i 条记录（i 从 0 开始）的训练目标为：

```text
真实块编号 b(i) = floor(i / B)
总块数 M       = ceil(n / B)
```

模型学习的是该区域内部的块位置，不是整个数据集的全局位置。目录复用同一个 `BlockModel`，但设置 `B = 1`，此时训练目标就是 fence 数组下标。

模型保存的学习结果包括分段边界、斜率、截距、输出范围和误差半径；标签学习另外保存少量字节位置。不涉及神经网络层或反向传播。

### 3.2 从字符串得到数值坐标

模型首先取区域首尾 key 的最长公共前缀。对于有序区域，这也是所有 key 的公共前缀。数值编码从该前缀之后开始，读取固定数量 t 的字节，构建 9-bit 符号序列：

```text
字节值 c（0..255） → c + 1（1..256）
字符串结束 EOS    → 0

x = Σ symbol[j] × 2^(9 × (t - 1 - j))，j = 0..t-1
```

默认规划候选 `t = 2 / 4 / 7`，最多使用 63 bit。NUL 字节编码为 1，与 EOS 区分；短字符串在结束后补 EOS。

这种固定长度编码保持非递减的字典序关系，但允许不同 key 得到相同坐标。编码截断只影响模型输入，不截断真实 key；查询仍比较完整字符串。

### 3.3 分段与拟合

`BlockModel::fit` 根据分段预算，将有序训练记录划为连续段。每段的目标记录数为 `ceil(n / segment_budget)`；若边界处编码值相同，就向后扩展，保证相同坐标不被分配给不同预测器。实际段数可以少于预算。

一段保存：

- `x_min / x_max`：编码坐标范围。
- `y_min / y_max`：该段记录覆盖的真实块编号范围。
- `slope / intercept`：局部线性函数参数。
- `radius`：这一段的最大绝对块预测误差。

当 `x_min != x_max` 时，线性函数通过段的两个端点拟合：

```text
slope     = (y_max - y_min) / (x_max - x_min)
intercept = y_min
y(x)      = intercept + slope × (x - x_min)
预测块 p  = round(clamp(y(x), y_min, y_max))
```

当所有坐标相同时，斜率取 0、截距取输出范围中点。计算坐标差时先在整数域做减法，再转换为浮点数。

推理时，按照各段的 `x_max` 有序查找使用的段；超过全部段上界时使用最后一段。预测值被约束在该段的输出范围内。

### 3.4 误差认证与候选窗口

训练逐键计算真实块编号与预测块编号的绝对误差，取最大值作为该段的 `radius`。随后通过实际推理使用的选段和窗口计算路径，再次验证每条基础记录是否被覆盖。

只有所有段满足误差预算，且逐键覆盖验证通过，模型才标记为 `certified`。默认叶区域的误差预算为 1 个块；目录训练使用固定的 2 个位置误差预算。

给定预测块 p 和误差半径 r，候选块窗口采用左闭右开区间：

```text
block_lo = max(0, p - r)
block_hi = min(M, p + r + 1)

record_lo = block_lo × B
record_hi = min(n, block_hi × B)
```

这项认证保证已有基础 key 的真实块位于查询窗口内。任意未见查询的目录前驱位置则另外通过真实 fence 边界验证确定。

`locate(key)` 一次返回窗口和预测块 p；`window(key)` 是只取窗口的兼容接口。预测块优先查询复用这次推理，不再额外调用模型。

## 4. 初始构建与模型规划

### 4.1 `bulk_load` 构建流程

`bulk_load` 在新实例上调用一次，输入必须已经按完整 key 严格排序且无重复；索引会检查该条件，不在内部重新整理输入。

构建顺序如下：

1. 保存基础输入的借用引用，并按 `region_size` 划分连续 ID 区间。
2. 为每个区间训练叶模型和标签配置。
3. 对未认证且记录数大于 64 的区域，按中点递归划分并重新训练；小区域可保留精确有序搜索路径。
4. 按键序连接所有叶区域的 `next` 指针。
5. 每次将至多 `directory_fanout` 个同层节点组成一个目录，提取 fence 并训练目录模型。
6. 自底向上重复分组，直到形成根节点。空输入形成一个空叶根节点。

### 4.2 原对照版本的叶模型与标签联合选择

完整规划枚举以下模型配置：

| 维度 | 候选 |
| --- | --- |
| 块大小 B | 16、32、64 条记录 |
| 编码字节数 t | 2、4、7 |
| 分段预算 | 1、2、4、8……，不超过 `max_segments` |

首先保留通过认证的模型，并按以下代价代理排序：

```text
model_cost = 0.2 × 编码字节数
           + 平均候选块数
           + 0.08 × 模型动态数组容量字节数 / 区域记录数
```

然后只对代价最低的至多两个模型评价标签配置，以 `model_cost + tag_cost` 选择最终组合。这是两阶段、有候选预算的局部规划；代价系数是实现中的固定常量。

若候选均未通过，代码使用块大小 32、编码长度 7 和完整分段预算保留一次最终拟合结果，再由构建或维护流程根据认证状态决定分裂或精确查询。

这套逻辑对应 `legacy_planning_cost`，仅通过两项已接受优化均开启的 `block-residual-delta-shortdir-first` 保留为第三项消融参照；早期四个独立工厂和单项开关变体已删除。另两个工厂使用下文的实际工作量目标，不混淆两套规划器。

### 4.3 实际查询工作量规划

新规划器以 16 项标签批次为单位模拟候选访问，不再将候选块数直接当作查询工作。64 条记录的完整逻辑块是四个批次，三个 16 条记录的块是三个批次；末尾不足 16 项时单列标量项。

`QueryWork` 记录批次、标签加载项数、标量尾项、完整 key 验证次数、逻辑比较字节数、后缀哈希字节数、特征步数与额外相对 64B 字节窗口。完整目标为：

```text
cost = 编码字节数 × 编码系数 + 分段查找层数 × 分段系数
     + 实际访问标签批次数 × 批次系数 + 标量尾项数 × 标量系数
     + 完整 key 验证次数 × 固定验证系数 + 比较字节数 × 字节系数
     + 哈希固定成本 / 后缀字节成本，或残差标签固定成本 / 特征步数 / 额外窗口成本
     + 自有模型和验证元数据容量 / 区域记录数 × 空间系数
```

模拟访问顺序与运行时相同：从左到右，或先预测块、再左区间、再右区间。命中批次中的全部标签加载计入成本，但只计到命中 lane 为止的完整 key 验证；之后的碰撞不计。未命中则检查整个认证窗口，不缩小范围。用有序 `(tag, local-position)` 数组查计数，避免对所有训练 key 两两比较；只有实际需要验证的候选才评价字符串比较字节。

每个区域从最多 128 个等距位置中固定种子洗牌，分为至多 64 个字节特征拟合样本和 64 个独立策略选择样本；单记录区域共享唯一位置。局部负查询由各自样本独立变异产生、逐一确认不存在，并限制在区域首尾键之内；至多 16 个。规划使用固定 90% 命中 / 10% 未命中先验，不读取正式 benchmark 的 `miss_ratio` 或查询；无法构造负查询的小区域不虚构零成本 miss。

模型仍枚举块大小 16/32/64、编码长度 2/4/7 和分段预算。先用包含实际提前返回批次数的乐观成本筛选，保留至多四个模型，再逐一评价允许的标签及扫描策略。残差字节位置在拟合样本上按新目标贪心增加，仅接受成本下降的新增位置；最终组合按独立策略样本选择。这是有预算的两阶段规划，不宣称穷举所有模型/特征组合的全局最优。

### 4.4 独立校准与配置冻结

`blocklearn_calibrate` 只生成固定种子的独立合成字符串、标签和比较对象，不接受数据集或查询文件。它在当前编译配置下测量编码、模型选段、SIMD/标量标签比较、相等比较、哈希和相邻/分散字节特征的原语成本，使用五轮中位数与长度差分估计正系数。极小或受噪声影响的差分下限为 0.01 ns/单位。

`space_byte` 是一次实测 32B 标签批次成本摊到字节的容量权衡代理，不是 DRAM miss 或 RSS 预测；比较字节数、相对 64B 窗口和线性原语成本也不是对完整硬件缓存行为的精确建模。优化收益由正式端到端实验验证，不把成本估计当作真实查询延迟。

统一实验入口在读取数据/查询之前校准一次，或验证并复制 `--planner-costs` 指定的既有独立配置。系数文件路径通过 `BLOCKLEARN_COST_PROFILE` 传给全部正式、正确性和阶段诊断进程；文件及 SHA-256 保存在输出目录，结束时再次核验。模型实例只在 bulk-load 之前加载一次，不在查询或插入中重新校准。不提供配置的新工厂在 bulk-load 明确拒绝，而不是偷偷使用未校准的常量。直接 C++ 测试可显式提供单位权重，不将这些测试权重作为性能配置。

配置另记录 SIMD 目标与 Debug/Release 类型，加载时拒绝不一致的文件。x86 的校准程序与模型核心同时使用 AVX2（配置支持时）或标量路径，避免用标量核的耗时选择 SIMD 查询布局。

### 4.5 目录模型选择

目录将子节点最小 key 组成有序 `fences`，使用 `B = 1`，枚举 2 / 4 / 7 字节编码和相同的分段预算序列。在认证通过的模型中，按原有 `legacy_planning_cost` 选取代价最低者。目录不扫描叶标签，因此不套用叶的 SIMD 批次成本。没有通过认证的目录模型时，直接使用完整 fence 数组的有序搜索。

开启 `short_directory` 时，另为目录构建 `ShortDirectory`：剥离 fence 的公共前缀，按相同 9-bit/EOS 规则编码后续七个符号，每个结果用一个 `uint64_t` 保存。编码有序但不保证唯一。不同编码直接确定字符串顺序，相同编码必须比较真实 fence；它不是哈希表，也不近似决定子节点。

构建时计算不同编码的数量，少于 fence 数量的四分之一则不采用短编码查询路径，保留原有模型/精确路由。这是固定的区分度启发式，不是查询热度缓存或学习代价模型。未采用的编码数组仍计入内存。原目录模型保留，供退回原路径时使用。

## 5. 残差感知字节标签

### 5.1 标签的角色

`TagPlan` 保存最多四个完整 key 的绝对字节偏移，默认选择上限为两个。查询读取这些位置的字节，将其与 key 长度混合，生成 16-bit 标签；不存在的位置使用 EOS 符号。配置也可以选择零个字节位置，此时标签仍包含长度信息。

标签只用于相等候选的快速过滤，不保持顺序，不参与区域路由，也不替代完整 key 验证。同一个 key 在同一标签配置下总是得到相同标签。

这里的“残差感知”指特征选择依赖模型预测后剩余的候选集合：目标是区分同一预测窗口内的 key，而不是直接回归数值误差或全局最大化字节熵。

### 5.2 特征学习

候选位置从公共前缀后的前八个字节，以及后续范围中八个间隔位置产生，去重后最多十六个候选。标签计划以绝对偏移保存这些位置，便于后续合并时复用。

`evaluate_tags` 对一份候选计划执行：

1. 为全部训练记录生成 `(真实块编号, 标签)`，排序后用于计数。
2. 按确定性等距位置抽取至多 128 条训练 key。
3. 用模型计算每个抽样 key 的候选块窗口。
4. 统计窗口内与查询标签相同的记录数，并对抽样查询取平均值 C。

C 包含被查询的训练记录本身，表示需要进一步精确验证的候选数量代理，不是未命中查询的假阳性概率。

`learn_tags` 从不读取特征字节的计划开始，逐步尝试增加一个尚未选择的位置。初始学习使用的评价函数为：

```text
tag_cost = C + 0.04 × 已选位置数
             + 0.12 × max(0, 已选位置覆盖的相对 64B 窗口数 - 1)
```

只有总代价严格下降时才接受新增位置，否则停止。相对 64B 窗口根据 `offset / 64` 估计，实际字符串地址的对齐不由该估计决定。

### 5.3 候选批量筛选

`tag_probe.h` 中的 `tag_mask` 一次处理至多 16 个标签，返回匹配位置的位掩码：

- 编译启用 AVX2 时，完整 16 项批次使用 256-bit 比较。
- ARM64 上，完整批次使用两组 NEON 向量比较并合并掩码。
- 其他平台和不足 16 项的尾批次使用标量比较。

查询逐个取出掩码中的匹配位置，再访问对应 ID 和真实字符串。每次向量加载均限制在实际数组范围内。标签的数组布局与逻辑块大小相互独立，一个候选窗口可以包含多个 16 项批次。

## 6. 点查询流程

### 6.1 目录路由

`leaf_for_traced` 从根节点逐层调用 `child_position_traced`：

1. 开启且可用的短编码路径先比较公共前缀：查询前缀小于/大于所有 fence 的公共前缀时，直接取首/末子节点；否则编码查询后缀。
2. 在连续短编码数组上二分求前驱。每次比较若编码相同，则转为完整 fence 比较；随后按相同规则确认真实前驱范围。
3. 未开启、区分度不足或短编码路径不能确认时，使用原目录路径：已认证且前缀匹配的模型给出候选 fence 窗口，在其中 `upper_bound`，并用真实 fence 验证范围。
4. 原模型路径不可用或验证失败时，在完整 fence 数组上执行 `upper_bound`。

中间子节点的范围条件是：

```text
fences[p] <= key < fences[p + 1]
```

首个子节点向负无穷扩展，最后一个子节点向正无穷扩展。因此小于全局最小键或大于全局最大键的查询仍能得到确定的叶区域，最终由叶内查询返回未找到。

### 6.2 叶区域查询

进入叶区域后的实际顺序是：

1. 对启用标签的版本，按当前区域配置生成查询标签。
2. 先遍历局部 `delta`；标签通过后比较完整 key，命中即返回 value。
3. 基础区为空时返回未找到。
4. 基础模型未认证时，对整个有序 `ids` 进行 `lower_bound` 和完整 key 验证。
5. 基础模型已认证时检查公共前缀；不匹配则基础区不可能包含该 key。
6. 一次推理计算预测块和候选块窗口，换算为 `ids` / `tags` 的记录区间。
7. 完整 key 版本在窗口内二分；标签版本分批筛选，再精确验证匹配记录。默认从窗口左端开始；开启 `predicted_first` 时依次检查预测块、窗口中预测块左侧区间、右侧区间。
8. 所有候选均不相等时返回未找到。

完整 key 版本的 delta 检查直接比较字符串。delta 在基础模型前缀检查之前查询，新插入的 key 即使缩短了区域公共前缀，或处于旧模型编码范围之外，也可以被正确找到。

预测块优先只重排已有窗口，不缩小认证范围。三个区间不重叠且完整覆盖原窗口；每段仍按 16 个标签批量检查，最后不足一批时不越界读取。命中可在预测块提前结束，未命中则遍历完整窗口。当前顺序是固定策略，没有学习误差直方图，也没有省略尾部候选。该开关仅适用于标签验证配置。

区域自适应版本中，`-first` 表示允许预测块优先；区域可按新目标选择上述两种完整扫描顺序之一。标签生成读取区域保存的 `tag_kind`，分别使用普通后缀哈希或该区域的学习字节位置；delta 与基础标签始终使用同一配置。原版本和固定残差成本对照的 `-first` 仍表示固定启用。

### 6.3 精确性的来源

查询依赖以下关系：

- 目录通过无歧义的有序短编码、编码相同时的真实 fence 比较，或原有边界验证/完整有序搜索定位区域。
- 每个已认证基础 key 的真实块均被它自己的预测窗口覆盖。
- 相同 key 的标签不会因碰撞而被排除；碰撞只增加待验证候选。
- delta 独立于旧基础模型检查。
- 只有完整 key 相等才返回对应 value。

因此模型误差和标签碰撞影响候选数量，而不会被当作近似查询答案。`find` 返回 `optional<uint64_t>`；value 为 0 仍表示一次有效命中。

## 7. 在线插入与局部维护

### 7.1 追加到区域增量区

启用写入的实例通过 `insert(key, value)` 执行：

1. 调用精确 `find` 检查重复；已有 key 返回 `already_exists`，不覆盖旧 value。
2. 将新记录复制到 `inserted_`，分配稳定 ID。
3. 沿真实范围目录递归定位所属叶区域。
4. 按该区域当前配置生成标签，将 `{id, tag}` 追加到 `delta`。
5. delta 未达到 `delta_capacity` 时，保持基础模型和数组不变。

delta 是局部无序向量，不是全局缓冲，也不要求每次插入维持有序。基础区与 delta 中同一个 key 不重复存放。

### 7.2 合并与重新拟合

delta 达到阈值后，同步执行局部维护：

1. 收集基础 ID 和 delta ID，按完整 key 排序。
2. 将排序结果作为新的基础 `ids`，清空 delta 的有效内容。
3. 区域记录数未超过 `region_size` 时，优先复用旧模型的块大小、编码字节数和实际段数，重新拟合并逐键认证。
4. 快速重新拟合未通过时，转入完整候选规划。
5. 根据区域大小与最终认证状态决定保留当前叶区域或进行分裂。

每次重新拟合都会更新公共前缀、模型参数和误差半径；启用标签且模型已认证时重建基础标签数组，否则不保留该数组。复用的是模型配置，不是跳过对新增数据的训练或认证。

新规划器也优先重新拟合旧模型，并用新工作量目标评价原标签/访问策略。每八次快速合并，或成本估计超过旧值 1.25 倍时，对当前已认证模型重新学习并选择标签/顺序；重新拟合失败时才执行完整模型候选规划。标签种类、特征位置、前缀或访问顺序改变后重建全部基础标签。配置更新只发生在 delta 已合入并清空时；`train_work_leaf` 明确拒绝在非空 delta 下更换配置。

### 7.3 标签配置的复用与刷新

快速重新拟合通过后，优先复用 `TagPlan` 的绝对字节位置。满足下列任一条件时，重新评价旧标签配置：

- 自上次检查以来，快速合并重新拟合次数达到 8。
- 新模型的平均候选块数超过旧值的 1.25 倍。

如果评价得到的平均匹配候选数大于 3，重新执行字节位置学习；否则保留原配置。检查后重置维护计数。进入完整规划但请求复用特征时，也会重新评价旧计划，再决定是否重新学习。

### 7.4 叶区域、目录和根的分裂

合并后超过 `region_size`，或者区域超过 64 条且模型仍未认证时，当前叶区域按有序 ID 的中点分为左右两部分，分别训练模型和标签。右叶接入 `next` 链，父目录插入相邻子指针。

每次递归插入返回时，父节点比较子节点的旧最小 key 与新最小 key。发生子节点分裂或最小 key 改变时，更新 fence 并重新训练该目录；无结构和边界变化的路径不重新训练目录。

启用短编码目录时，每次目录重训同时刷新公共前缀、全部编码及区分度标记。因此新增最小键、子节点分裂、目录分裂和新根都会更新路由元数据，不使用旧编码定位新结构。

目录的子节点数超过 `directory_fanout` 时，同样按中点分裂，分别重建 fence 和模型，并向父层传播。如果根分裂，则创建包含左右两个子节点的新根，树高增加一层。

所有合并、训练和分裂均在当前插入调用内同步完成。

## 8. 有序接口与运行约定

| 接口 | 行为 |
| --- | --- |
| `descriptor()` | 返回实现身份、键域和各操作支持情况 |
| `bulk_load(rows)` | 新实例调用一次；检查严格字节排序、唯一性和 ID 容量，建立全部层次 |
| `find(key)` | 精确点查询，返回 value 或空 optional |
| `insert(key, value)` | 启用写入时插入新键；重复键不覆盖 |
| `scan(lower, limit)` | 返回至多 limit 条 `key >= lower` 的有序、拥有字符串的记录 |
| `range_sum(lower, upper)` | 对闭区间求 value 和，按 uint64 模 2^64 累加；反向区间返回 0 |
| `update / erase` | 声明为 unsupported，调用抛出异常且不修改数据 |
| `memory_usage()` | 返回自有结构、适配层和保留输入的分项估计 |
| `statistics()` | 返回维护事件、按需查询计数和当前树结构统计 |
| `validate()` | 审核模型覆盖、边界、标签、ID、叶链及全局顺序 |
| `profile_find(key, profile)` | 与普通查询共用算法，另行记录查询阶段时间 |

`scan` 从 lower 所属叶开始，沿 `next` 向后遍历。每个访问区域临时收集基础和 delta ID，必要时局部排序，再从 lower 的有序位置输出。`range_sum` 使用同样的区域次序，并在超过 upper 时结束。

索引的运行约定是单线程、内存驻留、无持久化状态。实例在成功 `bulk_load` 后使用；不支持的操作按统一接口抛出 `UnsupportedOperation`。

## 9. 配置与实现版本

### 9.1 配置参数

| 参数 | 默认值 | 作用与取值约束 |
| --- | ---: | --- |
| `region_size` | 1024 | 初始区域大小与动态区域分裂阈值；16..2^20 |
| `directory_fanout` | 64 | 目录分组扇出与分裂阈值；4..1024 |
| `delta_capacity` | 16 | 增量合并触发条数；1..region_size |
| `max_segments` | 8 | 模型分段预算上限；1..32 |
| `max_block_error` | 1 | 叶模型允许的最大块误差；0..16，目录另用固定值 2 |
| `tag_features` | 2 | 标签读取字节位置的上限；0..4 |
| `instrument` | false | 是否记录查找次数、完整 key 比较、标签检查和目录回退等查询计数 |
| `short_directory` | false | 启用有区分度的目录短编码精确路由 |
| `predicted_first` | false | 标签查询优先检查预测块，未命中仍查完认证窗口 |
| `verification` | residual | 完整 key、普通哈希标签或学习字节标签验证方式 |
| `workload_planner` | false | 实际工作量规划；固定新工厂开启，原工厂不变 |
| `cost_weights` | 未提供 | C++ 可显式给出测试/配置权重；否则新规划器在 bulk-load 加载冻结校准文件 |
| `allow_insert` | true | 是否开放在线插入 |

工厂接受区域大小、目录扇出、delta 容量、分段/误差预算、标签特征上限及 `instrument` 参数，检查重复、格式和范围。三种工厂均固定启用短目录；`predicted_first` 固定为开启或允许区域选择，不接受通过参数覆盖两项已接受的优化。验证方式、插入能力及规划开关由工厂决定，成本系数通过独立校准文件加载。直接 C++ `Options` 仍可配置查询原语，用于内部正确性测试，不代表保留早期 benchmark 入口。

### 9.2 当前三个工厂与第三项消融

| 实现 ID | 规划与标签 | 扫描策略 |
| --- | --- | --- |
| `block-residual-delta-shortdir-first` | 原规划目标、残差标签，保留作参照 | 固定预测块优先 |
| `block-residual-delta-shortdir-first-cost` | 校准工作量规划，只允许残差标签 | 固定预测块优先 |
| `block-adaptive-delta-shortdir-first` | 校准工作量规划，每区域选择哈希/残差标签 | 每区域选择左到右/预测块优先 |

三者均启用目录短键、支持在线插入，共用原有区域边界、分裂阈值和精确性约束。第一项到第二项评价整个新规划器包；第二项到第三项评价标签种类和扫描顺序的联合选择，不单独归因于某个开关。独立哈希家族和其他早期入口/manifest 已移除；哈希标签原语仍是自适应模型的区域候选。自适应区域边界不在本次实现范围。

统一实验入口和 mixed runner 的 `all` 默认执行三个模型及 ART/HOT，共五个实现。`--ablation planner` 显式选择同一矩阵；旧目录/预测块单项消融命令会拒绝，不兼容映射为新实验。

## 10. 内存统计与可观测性

### 10.1 内存组织

基础记录引用占 4B/ID，启用标签时另有 2B/基础标签。总空间还包括统一节点对象、数组容量、目录指针与 fence、分段参数、delta 以及真实记录存储。短编码数组按容量另计 8B/项，只在开启时分配；`ShortDirectory` 对象内联于统一节点，其固定对象开销也存在于关闭开关的同版本对照中。

`memory_usage` 按容器容量和对象大小统计自有结构，并将全部借用输入行及字符串容量计入 `retained_input_bytes`。新增行及其字符串由索引拥有，计入 `index_owned_bytes`。字符串的内联存储与堆存储分别处理，避免重复计算 SSO 字符串空间。

这是分项容量估计，不是进程峰值 RSS；统计口径不含分配器管理开销、deque 备用块和训练/合并临时峰值。

### 10.2 计数、审核与阶段诊断

维护事件包括区域训练、合并、叶分裂和目录分裂。开启 `instrument` 后，查询路径另行计数；插入时的重复检查调用 `find`，也属于查询计数。`statistics` 同时遍历当前结构，返回叶数、目录数、树高和 delta 条数。

`tag_batches` 记录实际基础标签筛选调用次数。阶段 CSV 另外报告已认证非空区域中使用哈希、残差及预测块优先的数量；这些配置数和全样本查询计数只在 `all` 行给出，不伪造 hit/miss 分项。

`validate` 检查目录 fence 是否等于子节点当前最小 key、fence 和叶链是否有序、记录 ID 是否完整且唯一、已认证基础模型窗口是否覆盖全部基础 key，以及启用的基础标签和 delta 标签是否与当前配置一致。

短编码启用时还逐目录检查公共前缀和每个 fence 编码是否与当前真实边界一致。

`find` 与 `profile_find` 通过模板共用同一查询算法。普通查询使用空记录器；诊断查询使用计时记录器，将目录路由、叶模型、标签生成、标签筛选、完整 key 验证、delta 检查、精确回退和其他控制流分开记录。嵌套阶段使用独占计时，诊断时间包含记录器开销。运行方式和报告口径见 [实验入口说明](experiments/README.md)。
